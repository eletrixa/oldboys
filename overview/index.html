The problem we picked

Recruiters, salespeople and investors spend hours stitching one person together from scattered profiles and registries, then act on a hunch with no sources.

01

Which hits are the same person?

Search returns four people called Jan Novák. Three are the wrong one. Most tools quietly merge them.

02

What matters for this goal?

A recruiter needs tenure and public work. An investor needs the registry and who else sits on the board. Same person, different questions.

03

What is actually proven?

In a 2026 study, 3 to 13 percent of citation URLs produced by deep-research agents never existed. None of the four main open-source agents check their own citations.

The bet

The jury does not score scraping or summarising. It scores four things: identity resolution, goal logic, provenance, and whether a person can follow how the report was built. Everything we build lands on one of those.

So the product is a claim card, repeated.

Every sentence in the report is one card. It says whether it is a fact or an inference, how confident we are, which source it came from, and what contradicts it. Goals pick which cards exist. Gaps are cards too.

How it works

One subject, one anchor, one goal in. The run streams its decisions to the screen as it goes, so the person watching can see why the report says what it says.

  1. Find candidatesGoogle search through an Apify actor, with the anchor (city, website or IČO) in the query. Every hit becomes a candidate, not a fact.
  2. Line them upEach candidate gets a score from anchor match, cross-links between profiles and avatar similarity. Above the threshold we merge. Below it, the run pauses and asks you to pick. Uncertain ones stay separate as "possibly the same person" instead of being merged.
  3. Fetch what the goal needsEach goal is a fixed recipe of steps. Due diligence calls the Czech business registry for statutory bodies. Hiring calls GitHub. If a source comes back empty, the recipe runs its declared fallback and records a gap. It never silently moves on.
  4. Extract claims with a quoteThe model has to attach an exact quote from the stored excerpt to every claim. No quote, no fact.
  5. Verify, then verify againA plain string check confirms the quote is really in the excerpt and the URL really came from a fetch we logged. Whatever survives goes to a second model that can only downgrade. It cannot promote.
  6. Answer the goal's questionsThe report is the goal's question list, answered card by card. Unanswered questions appear as gaps with the reason.

What's different

Three things the case studies show nobody ships by default.

Citations are checked before they are shown

Commercial enrichment tools give you a confidence number. Open-source research agents give you links that sometimes do not exist. We check the quote against the fetched text and refuse the claim otherwise.

Namesakes are a visible step, not hidden magic

You see the lineup. You see the score and the evidence behind it. When the system is not sure, it asks instead of guessing. Borrowed from how Sayari handles entity graphs.

The goal changes the investigation, not the headings

Hiring and due diligence share fewer than half their steps and none of their questions. Run both on the same person and the diff view shows which claims appeared, disappeared or changed.

Gaps are a feature

A recruiter trusts a tool that says "no evidence" more than one that fills the space. The gap card says what we looked for, where, and why it came back empty.

Czech registry as the anchor

ARES v3 gives us the company, its seat, and its statutory bodies as JSON, free, no key. Most teams will stop at LinkedIn. The jury is Czech.

Every call is on the ledger

Each actor run and model call is logged with cost and time. The cached demo run for the video is a replay of that ledger, labelled CACHED. You can open it.

The uncomfortable ones

Nobody has tested the actors yet. The first hour is a source reality check, not a Next.js scaffold.
A dynamic tool-calling loop is cooler and riskier. We ship a fixed recipe per goal with two real branches, and add re-planning only if there is time at T+7h.
The UI will eat the night if we let it. UI work waits until the goal-diff test passes.
Ten percent of the score is a README section that would otherwise get written at 5am. It starts now.

Architecture

We compared three shapes. A fixed recipe in one process, a dynamic agent loop over the Apify MCP server with Postgres, and a CLI that writes a folder. Six independent reviewers argued for and against each. The fixed recipe won, built with the CLI option's ledger-first discipline.

If something slips

No end-to-end run by T+5h means we freeze scope to one goal, due diligence, and one subject. A working narrow demo scores more than a wide broken one. A fixed recipe that finishes beats a clever loop that does not.

What we will say out loud

The honesty criterion is ten percent of the score and the cheapest ten percent to earn.

LinkedIn coverage depends on actor availability that night. The README will say which runs were live and which were cached.
Avatar matching compares hashes across the profiles we fetched. It is not a web-wide reverse image search.
Registry coverage is Czech only. Other countries come through search results.
We do not infer health, politics, religion, ethnicity or sexuality. The filter is a classifier plus a post-check, not a proof.
Confidence levels are rule-based: high means two independent sources agree, medium means one source, low means inference. They are not calibrated.
Raw scraped data has a time to live and a purge button. It is deleted after judging.
